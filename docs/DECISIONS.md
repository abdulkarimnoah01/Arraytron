# Decisions and non-obvious findings (one line each, newest last)

- 2026-10-04: A HIP records its HDA's absolute library path. Moving an HDA before migrating the HIPs that use it degrades the nodes, and saving freezes the damage. Always use `tools/archive_release.py`.
- 2026-10-09: Symptom of that damage in a production scene (Electric_State layout v0012, two v0.1.5 nodes): the node warns "using an incomplete asset definition", has `children 0`, library "Embedded", and passes its input through without instancing. The parameters are intact. Repair: `hou.hda.installFile(<archived .hda>, change_oplibraries_file=False, force_use_assets=True)` then `node.matchCurrentDefinition()` on each node. `change_oplibraries_file=False` keeps the artist's Houdini preferences untouched. Verify with the node's `children` count, `warnings()` and the PointInstancer at `outputpath`.
- 2026-10-09: Scenes of other projects that use archived Arraytron releases depend on `X:/Assets/HDAs/Arraytron/dist/archive/Arraytron_<id>.hda` staying at that path. Do not move or rename archive files without checking shots that use them.
- 2026-10-04: VEX has no `fmod` (use `x - p*floor(x/p)`); Hscript has `rad()`, not `radians()`; USD orientations are half-precision quaternions (compare with ~2e-3); `node.errors()` on an HDA instance can be empty while a child node holds the error.
- 2026-10-12: Physics Settle runs the `rbdbulletsolver` SOP inside the PointInstancer's SOP network (branch PHYSICS_PROXIES > PHYSICS_SOLVER, never connected to OUT_POINTS) and is stepped from Python with `solver.geometryAtFrame(start+step)`; the playhead is not touched and the main cook never depends on time. The result is frozen in `<Cache Folder>/<node>_<fingerprint>.bgeo.sc`; the file name is a hash of spawn state, proxies, colliders and every solver setting, so a stale cache cannot be applied. A hidden int parm `phys_cache_rev` that `bake()` bumps is what dirties PHYSICS_APPLY (it reads the file outside Houdini's dependency tracking).
- 2026-10-12: `hou.Geometry.createPackedGeometry(geo, point)` does NOT place the packed prim at `point` (it stays at the origin); position goes in the translation row of `prim.setTransform(Matrix4)`, which writes the point's P. With the scale baked into the packed hull, `prim.fullTransform()` is the exact instance matrix (rotation + translation, no pivot adjustment) of the prototype frame: orientation = quaternion of its 3x3, position = its translation row.
- 2026-10-12: `rbdbulletsolver` facts measured on 3 cm stones: `bullet_linear/angular_sleep_threshold` have no effect (results identical for 0.002 and 0.8), so sleeping cannot be used to stop creeping; `margin` must be a few percent of the thinnest stone (the 0.02 default is bigger than the stone and floats small ones 5 mm); `usescale` is unnecessary; packed uniform scale is honoured but the hull is built per stone with the scale baked in, so non-uniform scale is exact too; drag (`adddrag`, `drag_airresist`) is a quadratic law with terminal speed sqrt(g/k) (measured within 2%), and it is what turns a scattering pour into a tight pile. Stones never reach exact rest: the bake stops when at most 2% of the stones still move more than 8% of the median stone size or 0.15 rad in half a second.
- 2026-10-12: `hou.hipFile.clear()` unloads HDA libraries installed with `installFile` in the same session: install after every clear (the physics suite does, with `force_use_assets=True`). A Karma camera made by the Camera LOP has a near clip of 1 unit: a 1 m scene renders with black slices until `clippingRange1` is lowered.
- 2026-10-12: Roadmap numbering: Physics Settle (user request) is v0.4.0; the master plan's step 4 (Curve, Surface Scatter, shared alignment) becomes v0.4.5 / v0.4.6 so steps v0.5 to v1.0 keep their numbers.
- 2026-10-12: The suite log lines "error binding handle lopxform because its bindings already exist" appear only when an Arraytron HDA is re-installed (`installFile(..., force_use_assets=True)` after `hipFile.clear()`) in the same hython session; installing one or two versions once, with or without `force_use_assets`, prints none. A test-session artifact, not an HDA defect.
- 2026-10-12: Codex CLI folder: the Store package path changes with each update (26.930 -> 26.1007); team run scripts resolve it with `Get-AppxPackage -Name OpenAI.Codex*`.
- 2026-10-12: Hull vertex cap matters for detailed stones: a 90-vertex stone with a 24-vertex proxy (Draft) overlaps neighbours by 6 mm (23% of its thickness), 48 vertices still gave 2.2 mm; caps are now 24 / 96 / 256 (Draft / Standard / High). Draft is cheaper per frame but needs about twice the frames on small stones, so it is not faster overall unless the hulls are large. Bench: `tests/bench_physics.py` (env BENCH_ONLY=pebble for the 90-vertex rows only; keep the pebble under ~100 vertices, the SAT measurement is quadratic in edges).
- 2026-10-12: Stage geometry for Curve and Surface Scatter is read with pxr from a prim path on the Source Resolver's stage (`stage_curves`, `stage_surface` in src/arraytron_scatter.py), at its world transform. `shape_mesh` tessellated sphere / cylinder / cone / capsule with inward normals until v0.4.6 (lathe winding; X and Z axis shapes are mirrored by the coordinate swap, so their winding is reversed). An absent Ids attribute means an instancer with zero points: a zero-point scatter is allowed and warns on the SOP node.
- 2026-10-12: Surface slope = angle of the triangle normal from world up, so the default Slope Max of 90 excludes downward faces (a cube prim loses its bottom face); tests set 180 when they want every face.
- 2026-10-12: Mask (v0.5.0) removes points inside the Python SOP with `hou.Geometry.deletePoints` (no Blast SOP needed), keeps survivors' ids, and writes `f@maskscale` only when the effect includes Scale, so the Prototype Assignment VEX (`vex_v050`) multiplies it in last and stays bit-identical without a mask. Sequential selection now uses `@ptnum` instead of `i@id` for the block position (equal without a mask). Image values are read raw with OpenImageIO (no colour transform). Mesh primvars are looked up from above through a cell grid of the triangles' XZ bounding boxes; the highest triangle wins.
- 2026-10-12: No Overlap (v0.5.1) sits after PROTOTYPE_ASSIGNMENT (sizes are known) and before the physics branch; instance bounding spheres come from `stone_spheres(proto_proxies())` of the physics module (hull centre and radius at the instance scale). `neighbor_pairs` finds candidate pairs with a sorted cell-key join (no scipy in hython); Remove is a greedy by index so earlier survivors never change.
- 2026-10-12: Physics demos are now built by `tools/build_demo_physics.py <railway|box>` for the CURRENT release; `tools/build_demo_physics_v04.py` is legacy (v0.4.0 only). `archive_release.py` copies `dist/arraytron_cache` to `dist/archive/arraytron_cache`.
- 2026-10-12: Interface (v0.5.2): `ui_layout()` in the builder regroups the flat `ParmTemplateGroup` into six Tabs folders; names, defaults, menus and conditionals are untouched (tested against the previous release). Mode panels are label headings plus parameters carrying an added `{ mode != N }` hide group (not folders). Collapsible sections are used only for specialist details: every built-in collapsible in H22 has default value 0, assumed to mean closed. Typing a number over a parm with a default expression (`$FSTART`) replaces the expression, in the UI and with `deleteAllKeyframes()` before `set()` in scripts.
- 2026-10-12: Grow (v0.5.2): the Python SOP `GROW` is last before OUT_POINTS and depends on time only while on (it evaluates the hidden parm `grow_frame` = `$FF`). PointInstancer LOP parm `importinvisids` writes an EMPTY time-sampled `invisibleIds` that overrides a default-time value, so it is set to `1 - grow_on`; the guide Python LOP authors `invisibleIds` (ids with `grow_hidden`) every cook. `CODEX_EFFORT` (env) overrides the reasoning effort in tools/team_run.py.
- 2026-10-12: Interface (v0.5.2 fix): top-level `folderType.Simple` folders render as stacked headings, not tabs; use `folderType.Tabs` (Houdini renames them tab_source, tab_source_1...; tests find tabs by label / ui_* names). Label parms with empty label show the parm name; set `is_label_hidden=True`. Combined demo must copy /obj as well as /stage (SOP prototypes live there).
- 2026-10-12: Brush (v0.6.0): strokes are stored as the resulting points (float32 xyz + normal + id, zlib, base64, at most 20,000) in the hidden string parm `paint_data`, not as stroke parameters, so the projection onto the surface happens once at paint time and the node never re-reads the surface per cook; new ids never reuse removed ones. Candidates come from hash(dab, k, seed). The viewer state is embedded with the same sections as SideFX's own HDAs (ViewerStateModule, DefaultState, ViewerStateInstall / Uninstall, ExtraFileOptions IsPython / IsScript / IsViewerState); the state name has the version in it so two versions can be installed.
- 2026-10-12: Test trick: the viewer state is exercised headlessly by exec'ing its source with `hou` replaced by a namespace whose GeometryDrawable is a stub, and feeding scripted events (it found the missing `paint_apply` argument). Mutation patches must target a function that is never replaced (`paint_decode.__globals__`), because a lambda's `__globals__` is the test file.
- 2026-10-12: Input sockets (v0.6.0) are labelled in the DialogScript only (`INPUT_LABELS`); the Prototype Bank menu labels stay `Input 2/3/4`, which the new socket labels start with. A curve is not an input of its own: it is a prim in input 1.
- 2026-10-12: HDA icon: `icon/Arraytron-Clean.svg` is embedded as the section `Icon.svg` and the type icon is `opdef:/<category>/<type>?Icon.svg` (`set_icon()` in the builder); HOM has no save-icon option, and `setIcon(file path)` would leave an external reference. Rendering in the network editor is GUI-unverified.
- 2026-10-12: Field Stack (v0.7.0): one Python SOP `FIELD_STACK` between MASK_PROCESSOR and VARIATION_PROCESSOR; rows are a multiparm with per-type parameters (all `field_*#`), shown by `{ field_type# != N }`. The first enabled row ignores its Combine; the running value is clamped after every row. Density uses the same per-id hash as the Mask with stream 21 and its own seed; Scale multiplies an existing f@maskscale instead of replacing it, so no VEX change was needed.
- 2026-10-12: Geometry tests for fields: point-triangle distance is exact (edges plus plane projection), degenerate triangles are segments, capped at the far distance so only nearby triangles (XZ grid) are tested; inside tests count +Y crossings with the query nudged by 1e-7 off shared edges (a ray through a diagonal would count twice and flip the parity).
- 2026-10-12: v0.8.0 merged No Overlap into Separation & Collision instead of adding a second spacing system: parameter names, the NO_OVERLAP node and the v0.5.1 behaviour are unchanged (only labels: folder 'Separation & Collision', menu 'Separation'); Priority and Avoid Geometry are new parameters on the same node (`overlap_priority`, `avoid_*`). The Id Order priority is the old index-order greedy removal, so saved scenes and tests are unaffected.
- 2026-10-12: Avoid Geometry in XZ mode measures to the OUTLINE of the footprint (edges not shared by two same-facing triangles, plus a covered-by-any-triangle test): distances to the triangles themselves would be 0 everywhere inside the footprint and give no direction to push; points inside the geometry (3D parity or XZ covered) can be farther from the surface than the search limit, so their search is widened by doubling.
- 2026-10-12: Cluster ids are cluster x 1000 + member (members capped at 999) so that adding clusters or members never renames existing points; centres are surface_points(seed) like Surface Scatter, members use hashes of their own id, and are projected with the Paint tool's projector (members off the surface are dropped).
- 2026-10-12: v0.9.0 camera work is one Python LOP `camera_optimize` AFTER the Bounds Transform (final world positions, Physics Settle and Grow included), not a SOP: it hides through time-sampled invisibleIds (merged with the ids Grow lists) and switches protoIndices; nothing is deleted. A Python LOP / SOP script text is a string parm: a `$FF` in a COMMENT is expanded and makes the node time dependent, so keep dollar signs out of embedded scripts (the time dependency comes from the hidden parm `cam_frame`, read only while Camera is on).
- 2026-10-12: LOD prototypes are extra bank-row prims appended to the PointInstancer's prototype list after the heroes (heroes keep their indices, so selection, physics proxies and overlap spheres are untouched); lod_levels takes the highest threshold passed, so unsorted thresholds are allowed; a missing level falls back to the next finer one.
- 2026-10-12: Primvars: the PRIMVARS wrangle always writes the point attributes and the PointInstancer's `attribs` copies only the ticked names (an expression on the HDA); Mask and Field Stack store maskweight / fieldweight point attributes for the mask and density primvars.
- 2026-10-12: v1.0.0 overrides are a multiparm table keyed on the stable id (not stored geometry), applied in the Python SOP OVERRIDES after the physics and before Grow, so a row edits exactly the instance that would be generated; Rotate is a local-frame post-multiplication (qmultiply(orient, delta), delta = R_z R_y R_x about fixed axes); rows with a missing id or prototype row are counted and ignored. No viewport picking yet (GUI work).
- 2026-10-12: Debug views are a Python LOP (debug_guide) that reads the SOP geometry (generator vs OUT_POINTS: rejected = generated ids not in the final points) and authors guide-purpose prims; it never touches the instancer. Export USD flattens the stage and copies the instancer subtree with Sdf.CopySpec into an anonymous layer, exports it and sets the up axis, so the file is self-contained.
- 2026-10-12: The master plan's Basic / Advanced split was NOT done as a global switch: the user-approved interface (Codex review, v0.5.2) uses fixed tabs and local disclosure (collapsible Details sections, mode panels shown by the Distribution Mode, features that are off hide their settings). v1.0.0 adds the Finish tab and the Optimize tab in the same style.
- 2026-10-12: tests/validate_production.py checks release hygiene (every docs/*.md indexed in docs/INDEX.md, manifest hashes, all-demos cook): run tools/make_manifest.py after the last build before it.
- 2026-10-12: The v1.0.0 fuzz test found two real crashes that no feature test had reached: the Debug LOP and the bounds_guide / grow_guide_line read SOP geometry that is None when the points fail to cook (bad prim path), giving a Python traceback instead of the node's readable error. Rule: any Python LOP that reads `node.geometry()` must handle None (raise hou.NodeError or skip). The fuzz also feeds bad prim paths on purpose.
- 2026-10-12: Shipping (v1.0.0): the installer copies the HDA to `%LOCALAPPDATA%\Arraytronersions\<ver>\otls` and writes `Documents\houdini22.0\packagesrraytron.json` (env ARRAYTRON, path $ARRAYTRON), like PhiAxis; demos live in `demos/` with their own copy of the HDA because the hips reference `$HIP/Arraytron_<ver>.hda`; two versions are kept for rollback. - 2026-10-12: Houdini 20.5 / 21 compatibility CHECKED (hython 20.5.445, 21.0.440): v1.0.0 does NOT work there. Cause: the HDA's compiler node is the Houdini 22 `pointinstancer` LOP (101 internal node types, only that one is missing); 20.5 and 21 have the older `instancer` LOP instead (method pointinstancer, internal SOP network, different parameter names: transformsourcemode, protoindexsrc / indexattr, no importsoppoints / createprotoarea / protodestrootprim / importinvisids / update modes). The HDA installs in 20.5 but the node cooks no PointInstancer. Everything else is portable: the whole PythonModule compiles and its pure functions run on Python 3.10 / numpy 1.24 and 3.11 / numpy 1.26, and all other node types exist. A probe showed the 20.5 `instancer` with an internal SOP network writes ids, protoIndices, orientations and primvars, BUT sorts the prototype list (here Barrel before Crate, not the pattern order) and puts them under `<output>/Prototypes/<original path>`, so a port must map prototype indices by path (the camera LOD table too) and the suites need version-aware paths. A port would be a separate build for 20.5 / 21 (own HDA folder and package) with its own test matrix.
- 2026-10-12: Houdini 20.5 / 21 build (v1.1.0, docs/PORT_HOUDINI_205.md): one builder, selected by the running hython (`versions.is_h205()`), writes `otls_h205/Arraytron_<ver>_H205.hda` with the same type name; old releases v0.3.0 to v1.0.0 also get H205 builds there so every "equals the previous release" test keeps its meaning in 20.5 / 21. The Houdini 22 build is unchanged.
- 2026-10-12: the 20.5 / 21 `instancer` LOP sorts prototypes and mirrors the source path under `Prototypes/`. Fix: `protosourcemode=second` with a Python LOP stage of top-level prims that **specialize** the bank prims (flat names `/Crate`, `/Rock2` like Houdini 22; a Reference arc gives the warning "Unable to relocate reference", Inherit / Specialize do not; the prim must be untyped or a Cube / Cone source loses its type), `protoindexsrc=pathattr` on a string point attribute, then a Python LOP restores bank order of the targets, `protoIndices` and child order and hides the sources. A real top-level source prim is copied with its children, so it keeps its own path.
- 2026-10-12: the 20.5 / 21 instancer writes `invisibleIds` as an (empty) time sample; a default-time value from a later LOP does not override a time sample in the same layer, so the guide writes Grow's list at that sample's time (no-op in Houdini 22).
- 2026-10-12: in 20.5 / 21 an HDA with `bindhandle ... lopxform` lines cannot be installed again after an unload in one process (stale bindings: "error binding handle lopxform because its bindings already exist", node type with no parameters; Houdini 22 only warns). `reloadFile` and a second install without unloading are fine; scanned-path HDAs never unload. Consequences: demo scenes of the 20.5 build record no HDA library (build with `HOUDINI_OTLSCAN_PATH=<project>/otls_h205;&`, `versions.ensure_installed`), the suites install a copy without the bindings (`tools/h205_compat.py`), `tests/validate_h205.py` checks the shipped file in a clean session.
- 2026-10-12: 20.5 / 21 API differences met: no `Geometry.pointCount()` (use `intrinsicValue('pointcount')`), `node.cook(force=True)` raises on a cook error and `errors()` reports the last cook, no Bullet `ground_margin`, `usdchecker` is a `.cmd`, the Karma settings LOP is `karmarenderproperties` (`tools/demo_compat.py`). Scenes saved by the 20.5 build open in Houdini 22 (hython, three demos) and cook the same.

- 2026-10-14: Imported Points (v1.5.0): SOP sources go through an Object Merge SOP inside the compiler (it keeps the dependency and the time handling of Houdini); USD sources are read with pxr in a Python SOP at the frame plus the offset (hidden parm `imp_frame` = the frame variable, read only in that mode; keep dollar signs out of the script text). The generator writes `id`, `align`, `srcscale`, `source_id`; `transforms.vfl` multiplies `v@srcscale` into the scale and the existing `p@align` hook rotates. Even Percent (selection mode 4) uses Fibonacci hashing in 32-bit integer arithmetic because VEX floats lose the quality for large ids (a float golden-ratio product failed at id 6831) and VEX has no shift operator (top bit dropped, the sequence stays low-discrepancy). Houdini maps the primvar names itself (Cd -> displayColor; v -> velocities in 22, v in 20.5 / 21): tests follow that.
- 2026-10-15: Paint tool fix after the first real GUI test (the brush stayed in the middle of the viewport and nothing could be painted): the viewer state now takes the mouse ray from `ui_event.ray()` (the call Houdini's own states, e.g. Paint Instances, use) instead of `viewport.mapToWorld(mouseX, mouseY)`; a plain click (reason Picked) paints one dab; every state callback is wrapped by `guarded()`: an error is printed to the Houdini console and shown in the viewport prompt instead of silently doing nothing (the tests set `STRICT` and re-raise). Lesson: a stand-in viewport cannot prove a viewer state works; the first GUI test found what 16 headless groups could not. The Paint-only demo (`tools/build_demo_paint_k_v150.py`) paints the letter K with the same brush functions.
- 2026-10-15: Paint shortcuts (v1.6.0) follow Houdini's own brush conventions (Ctrl erase, Shift smooth, Ctrl+Shift drag = radius) plus the wheel and a few keys; Alt and the middle mouse button are never consumed. Shortcut handling lives in `onMouseEvent` (resize drag, modifier decides the operation), `onMouseWheelEvent` and `onKeyEvent` of `src/arraytron_paint_state.py` and writes the node parameters directly, so the sliders and the state always agree; the prompt line is the live readout (the HUD API was not used: unverified). Lesson repeated: a version bump per change; v1.5.0 was rebuilt in place by mistake for a moment and restored from the shipped Release archive before v1.6.0 was cut.
- 2026-10-15: The Paint viewer state is the node's DefaultState, so Houdini enters it whenever the node is selected; `onEnter` must therefore never change parameters. `PaintState._ensure()` keeps the tool idle unless `mode==6` (Start Painting sets the mode, `paint_start`). Found by the user (selecting another node and coming back switched the mode to Paint).
