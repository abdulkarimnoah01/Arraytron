# Arraytron Stamp 0.9.3 (the light one)

A node for **placing instances by hand**: `arraytron::stamp::0.8.0`, built with `hython tools/build_stamp_light.py` (hython 22 or 20.5; `Arraytron_Stamp_v0.8.0.hda` and `Arraytron_Stamp_v0.8.0_H205.hda`).

It replaces Stamp 0.1.0, which was Arraytron's Instance Place mode in the full Arraytron network and was slow: every click rebuilt a table of rows (134 ms with 40 stamps, more with more) and recooked a network of about 1700 parameters. 0.2.0 is a node of its own, written to be as light as it can be:

* **One text parameter holds the stamps** (`Stamps`: a line per stamp, `x y z  rx ry rz  sx sy sz  prototype row  on`). Placing a stamp appends a line, one parameter write (0.6 ms), no rows to build.
* **One Python LOP** inside turns the text into a `UsdGeomPointInstancer` (300 stamps cook in about 5 ms). A stamp keeps its line number as its id, so deleting one never renames the others.
* **The ray goes against a `hou.Geometry`** built once from the meshes under Place On (its own acceleration structure: 0.04 ms for 180 000 triangles), not against every triangle with numpy as before. Without Place On the ground plane Y = 0 is used.
* The tool never sets the prompt line while the mouse only moves, draws a marker of about 30 points, and keeps no table in memory.

## Using it
Wire a stage with the ground and the props into the first input. Select the node and enter its tool (Enter in the viewport), or press a brush on the shelf of the Parameters pane. 0.6.0 is built like Houdini's Layout / Paint Instances tool (read from their installed files in 20.5 and 22): a **Brush** mode and an **Edit** mode, a brush shelf, Houdini hotkeys, the heads-up panel, a working set of prototypes.

### The Parameters pane
Above the parameters: the **shelf** (Place, Delete: a click enters the tool with that brush), the **cards** of the Prototype Bank, the **STAMPS** table and the **ASSET LIBRARY** (collapsible). The cards (0.7.0, like Houdini's Layout Asset Gallery): a **thumbnail** of every prototype (a software render at its first sample, so an animated asset shows its first pose; drawn one per timer tick, in the pane's own process, so a big bank never freezes it and no renderer is needed; instanceable assets such as Houdini's own samples included), **List / Grid / Large** views, a **search** box (every word must match the name, the prim path or the file), a **star** on each card (favourites come first; the star button filters them; kept in the hidden parameter `favorites`) and a **Set** filter (only the working set). A click makes that row the working set, Ctrl + click adds or removes one. The parameters are the tabs **Brush** (Transform, Asset, Advanced), **Edit** and **Options**, like the Layout tool's Brush / Edit / Options. The current tab is the parameter `mode1`: the Edit tab is the Edit mode of the tool, and Shift+B in the viewport changes the tab.

* **Brush > Randomization:** boxes Prototype (Random Prototype), Scale (Uniform Scale, Random Scale Min / Max), Rotation (Rotate, Random Rotate, Random Tilt) and Seed: what changes between one stamp and the next. **Asset:** the Prototype Bank, Prototype Row. **Placement:** Align To Surface (on by default: the up of the stamp is the smooth normal of the surface under the mouse), Offset, Sit On Surface (the bottom of the prototype, not its pivot, touches the surface or the stamp below), Smooth Normals, Snap Position, Snap Rotation, Drag Sets Rotation And Scale. **Paint**, **Group**.
* **Edit:** Selection (read only), Select All / None / Invert, Duplicate Selected, Delete Selected, Clear All Stamps. **Options:** Place Instances, Place On, Place On Stamps, Output Prim, Make Prototype Source Primitives Invisible, Parameters Pane (read only: whether the pane is loaded) and **Reload Stamp Pane**. If the pane could not be registered, the plain dialog shows this line saying so and what to press.
* **STAMPS table (replaces the raw text box, which is a hidden parameter now):** a row per stamp (#, On, Row, X, Y, Z, Rx, Ry, Rz, Scale). Edit a cell to edit the stamp (one undo step); the On cell is a checkbox. The selected rows are the selection of the Edit mode, both ways. It is a virtual table over the stamp rows: thousands of stamps cost nothing, and it is not read while it is folded.

### The viewport (hotkeys are Houdini hotkeys: Edit > Preferences > Hotkeys, "arraytron_stamp_093 Operation")
* **Place brush:** under the mouse a ring and **the prototype itself** (a ghost: its real geometry, lit, translucent; opaque-ish while you drag) show the next stamp with its rotation and scale (the same random draws the click makes; the bank row's own Scale, Scale Random and Rotation Offset included). A dense asset is shown as a lighter copy of itself (about 6000 triangles, points merged on a grid, so the silhouette stays whole). When the bank cannot be resolved the box is drawn instead. **LMB** click places; **LMB drag** sets rotation and scale (the stamp stays where you pressed, turns to face the mouse and grows until its footprint reaches it; a dial and a label show the angle and the scale). **Shift + LMB drag:** scale only. **Ctrl + LMB drag:** orient only, to increments (Snap Rotation, else 15 degrees). **Ctrl + Shift + LMB drag:** orient freely. **Mousewheel:** cycle the working set. Shift + wheel scales and Ctrl + wheel rotates the next stamp (also `[` `]` and `,` `.`); the keys `1` to `9` make that row the working set, `0` clears it.
* **Paint brush (0.8.0):** a ring of the brush radius lies on the surface under the mouse (each point cast onto the ground, so it follows a slope). **LMB drag** paints stamps inside the disc, one dab every 35% of the radius, **Ctrl + LMB drag** erases the stamps inside it (the ring turns red). A dab tries `Density x area x 0.5` candidates (stochastic rounding, at most 400), thins them towards the rim by **Edge Falloff**, casts each onto the surface along its normal and drops the ones closer than **Spacing** to a stamp that is already there, so painting over the same spot fills it up to the Spacing and stops. Paint goes on the ground (the surface of Place On), not on top of the stamps. The new stamps are the stamps a click would make (the Brush > Transform randomness, Random Prototype from the working set): one parameter write per dab, one undo step per stroke. **Shift + mousewheel** (and `[` `]`) change the radius, **Ctrl + mousewheel** the density, the plain wheel still cycles the working set. Settings: Brush > Paint (Radius, Density, Spacing, Edge Falloff).
* **Delete brush:** the stamp under the mouse shows red; click deletes it, press and drag over several and release deletes them all (one undo step). It always sees the stamps, whatever Place On Stamps says.
* **Edit mode (Shift+B):** click selects a stamp (Shift: add or remove), drag on nothing is a box select (Shift: add), a click on nothing clears. The selected stamps show yellow boxes and Houdini's **edit handle** (move, rotate, scale about the centre of the selection; one undo group per drag; only the selected lines are rewritten while dragging). **Z** held while dragging the handle duplicates the selection first. **Del** deletes the selection.
* **C** opens the brush menu (Place, Delete, Edit mode) and **B** the options menu (Align To Surface, Random Prototype, Drag Sets Rotation And Scale, Place On Stamps, Snap Rotation) at the cursor; the hints and the values of the next stamp are in the viewer's HUD panel (Shift + F1 hides it), which has a page per mode and brush.
* **Group brush (0.9.0):** one click stamps several prototypes. Radial layout (default): one member per selected card on a ring, their footprints times Brush > Group > Spacing apart; Count draws members from the selected cards by Weight; Shuffle Order mixes them per group. Custom layout: place stamps, select them in the Edit mode, press **G** (Brush > Group > Set Layout From Selected Stamps): the brush stamps copies of that cluster (offsets from its centre, rotations and scales kept); Reset To Radial Layout clears it (hidden parameter `group`, scripts: `stamp_group_capture`, `stamp_group_reset`, `stamp_group_add`). Drag turns and scales the whole group (its footprint reaches the mouse), Conform To Surface drops each member onto the surface under it, the preview shows every member (up to 12 as the prototype itself, the rest as boxes).
* **Paint falloff (0.9.3):** Brush > Paint > Falloff: Enable Density Falloff and Enable Scale Falloff, each with Edge Minimum, Falloff Width, Falloff Strength, Curve (Linear, Smoothstep, Smootherstep, Ease In, Ease Out, Custom Ramp), the scale one with a Center Maximum; presets Uniform, Soft Natural, Sparse Edges, Growth, Dense Center, Custom. Both read the distance to the whole stroke (a ribbon with a soft edge, no dab circles, the same stamps at any mouse speed). Off by default (the classic dab brush and its Edge Falloff). Scripts: `stamp_paint_path`, `StampPaintStroke`, `stamp_paint_preset`. See docs/PAINT_FALLOFF_TECH.md.
* **Group layouts and randomization (0.9.2):** Brush > Group > Layout: Radial, Square, Hexagon, Random Cluster, Line, Spiral, Custom. Groups are the same size by default (the Randomization tab's Random Scale is for single stamps); Random Group Scale, Random Member Scale and Random Member Rotation are off until you set them; Match Member Sizes scales every member to the median size of the selected prototypes.
* **Random button (0.9.0):** the shelf button Random is Random Prototype: every stamp (Place, Paint, Group Count) takes a random one of the selected cards by Weight; the preview shows the one that comes next.
* **The sheet edits many (0.9.0):** the bar above the table says what a cell edit reaches (Selected stamps: the selection when the row you edited is in it, else that row; All stamps) and how (Set, Add, Multiply). Row and On are always set. One undo step and one parameter write (`stamp_edit_rows`).
* **Managing stamps (0.9.1):** the STAMPS section has Delete, Duplicate, All, None, Invert and Clear All (asks first) under the table, Del in the table, and a right-click menu (also select / delete the stamps of the same prototype). A right click on a card selects or deletes its stamps (the tooltip and the List / Large views say how many use it). Scripts: `stamp_delete_many`, `stamp_duplicate_selected`, `stamp_select_proto`, `stamp_delete_proto`, `stamp_counts`.
* **The stamp cycle is visible (0.9.1):** the selected cards have an orange frame and a number (the order of the mousewheel), the line under the shelf names them, or says that none is selected and all are in play.
* **Working set:** the selected cards. The wheel cycles them, Random Prototype draws from them (by Weight); with none selected every enabled row is in play.
* The ray hits the stamps already placed too (Place On Stamps), so stamps stack; Place On takes several prims and basic shapes.

* **Prototype Bank (the rows of Arraytron's bank):** a multiparm; each row has Enable, **Source Type** (Prim Path, Input Connection, USD File, Group Children), Weight, Scale, Scale Random and Rotation Offset. A Prim Path row with an empty path is the built-in sphere (a new Stamp starts with it). Input Connection takes a prim of Prototype Input 2 / 3 / 4 (an empty path picks the input's only component or geometry), USD File references a file on disk (staged hidden under `<output>_Sources`, with an optional prim path in it), Group Children makes every child prim of `/Group` (or `/Group/*`, or a pattern `/Group/rock*`) a prototype of its own and a stamp takes one of them. A stamp stores its bank row number; the row's Scale, Scale Random and Rotation Offset are applied by the cook (the offset turns the prototype first), so changing a row changes every stamp of it. A row switched off is not a prototype (its stamps take the first enabled one). The node has four inputs: the scene and three Prototype Inputs, merged. SOP Geometry and the LOD prims of Arraytron's bank are not in the Stamp.
* **Asset Library (shared with Arraytron):** the same ASSET LIBRARY as Arraytron's (categories, search, thumbnails, Add to Bank, Asset Catalog, USD Files, Folder, double-click or drag). **Add to Bank** puts a USD File row into the Stamp's bank (the untouched first row is replaced, then rows are added); the card appears at once. The library is one JSON file per user (`ARRAYTRON_LIBRARY` or Documents/Arraytron/library), shared with Arraytron.
* **Randomness between stamps:** Random Scale, Random Rotate, Random Tilt, Random Prototype, Seed (Brush > Randomization). The same seed gives the same stamps and more stamps never change the earlier ones. The `Stamps` text (hidden parameter `stamps`, a line per stamp: `x y z  rx ry rz  sx sy sz  prototype row  on`) is still the data: the table, the tool and scripts (`stamp_add`, `stamp_edit_row`, `stamp_delete_many`, ...) all write it.

## Release, installer and updater (0.8.0, the first public release)
Arraytron Stamp is a product of its own: `INSTALL_STAMP.md` (shipped as INSTALL.md), `CHANGELOG_STAMP.md`, its own install folder (`%LOCALAPPDATA%\ArraytronStamp\versions\<version>`), package file (`Documents\houdiniX.Y\packages\arraytron_stamp.json`), variable (`ARRAYTRON_STAMP`), shelf (Arraytron Stamp > Check for Updates) and update source, so it never mixes with Arraytron's. It is built the way Arraytron's release is:
* `python tools/make_stamp_release.py` builds `release/stamp/`: `Arraytron_Stamp_v<ver>_Release.rar` (Install / Uninstall Arraytron Stamp.cmd, `install.ps1` from `installer_stamp/`, the two HDAs in `payload/h22/otls` and `payload/h205/otls`, the shelf from `toolbar_stamp/`, the demos built without a library record, the docs, the icon, the updater `src/stamp_update.py` + `src/stamp_update_ui.py`), `Arraytron-Stamp-<ver>.zip` + `version.json` (the update source files; the manifest names the product and the updater refuses another product's version.json) and `SHA256SUMS.txt`. The version is `STAMP_VERSION` in `tools/build_stamp_light.py`, the notes are the section of `CHANGELOG_STAMP.md`.
* `tests/validate_stamp_installer.py` proves it (the maker runs it): the installer in a sandbox (no preferences, install for 20.5 / 21 / 22 with the right build each, an unsupported 19.5 gets nothing, Arraytron's own package and folder untouched, payload complete, update keeps two versions, uninstall), clean Houdini sessions (the HDA is found from the package with its viewer state, pane, icon and help; the installed demo cooks with 300 and 11 stamps; three loads of the demo keep the parameters in 20.5), and the updater end to end (versions, Houdini range, the name guard, a changed zip refused, the zip installing itself, the update source order). Houdini 21's hython crashes on start with a clean preferences folder on this PC (the same for Arraytron's installer test): those checks are skipped with a message and the h205 build is covered by the clean 20.5 sessions and by `tests/validate_stamplite.py` in a normal Houdini 21.0.440 session (211 checks, run for 0.8.0).
* `python tools/publish_stamp_release.py` publishes to the public repo `abdulkarimnoah01/Arraytron` as the release `stamp-v<ver>` and the rolling release `stamp-latest` (the address baked into the package: `releases/download/stamp-latest/`). **Both are created "not the latest release"**: Arraytron's updater reads the repo's latest release (`releases/latest/download/`), so the Stamp's releases must never take that place. Only release files are uploaded; no source goes to the public repo.
